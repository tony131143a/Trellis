# Repository Package Map

These guidelines describe the current Arbor repository shape and how package
keys in `.arbor/config.yaml` map to source code and specs.

## Purpose

Keep Arbor package/spec routing aligned with the actual repository so
`get_context.py --mode packages`, task package binding, and future AI sessions
load the right guidance.

## Package Map

| Package key | Path | Package name | Spec path | Purpose |
| --- | --- | --- | --- | --- |
| `cli` | `packages/cli` | `@tony131143a/arbor` | `.arbor/spec/cli/**` | User-facing CLI, templates, migrations, dispatch scripts and the two platform configurators (Claude Code, StarFactory). |

Arbor is a derivative of Trellis; see `provenance.md` in this directory for the
rename table and the list of upstream packages and features that were removed
(`packages/core`, `docs-site`, `marketplace`, `channel`, `mem`, ...).

## Workspace

- `pnpm-workspace.yaml` declares `packages/*`; the only workspace package is
  `packages/cli`. There are no git submodules.
- The npm package is not published. Install locally with
  `pnpm build && (cd packages/cli && npm link)`.

## Contracts

- `.arbor/config.yaml` uses the stable Arbor package key `cli` rather than the
  npm package name. The key is part of spec paths and task package bindings.
- `default_package` is `cli`; new tasks without `--package` bind to CLI.
- Existing tasks keep their frozen `task.json.package`. Changing
  `.arbor/config.yaml` does not retroactively rebind old tasks.
- Package-context output is generated by
  `.arbor/scripts/common/packages_context.py`, which scans
  `.arbor/spec/<package>/<layer>/index.md` for each configured package.

## Checks

```bash
python3 ./.arbor/scripts/get_context.py --mode packages
git diff --check -- .arbor/config.yaml .arbor/spec
```
