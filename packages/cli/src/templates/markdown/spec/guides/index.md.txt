# Thinking Guides

> Questions to ask before writing code, to catch what you would not have thought of. Coding rules are not here: they live in the layer directories.

## Available Guides

| Guide | When to read it |
|-------|-----------------|
| [Code Reuse Thinking Guide](./code-reuse-thinking-guide.md) | You are about to write a helper, you see a pattern repeating, or you are changing a constant or config value |
| [Cross-Layer Thinking Guide](./cross-layer-thinking-guide.md) | A change spans three or more layers, a data format changes between layers, or you are adding an event, payload or config field |

## Search Before You Change

Before changing any constant, config key, path or name, search the whole repository for where it appears. This one habit prevents most "forgot to update the other place" bugs.

## Thinking Triggers

Read the [Cross-Layer Thinking Guide](./cross-layer-thinking-guide.md) when:

- [ ] The feature touches three or more layers (API, service, component, database)
- [ ] A data format changes between layers
- [ ] Several consumers need the same data
- [ ] You are not sure where a piece of logic belongs
- [ ] You are adding an event kind, a stored record, an RPC payload or a config field

Read the [Code Reuse Thinking Guide](./code-reuse-thinking-guide.md) when:

- [ ] You are writing code similar to something that exists
- [ ] The same pattern appears three or more times
- [ ] You are adding the same field in several places
- [ ] You are changing a constant or a config value
- [ ] You are creating a new utility or helper function

## Verifying AI Review Findings

Check every finding against the code before prioritising it; false positives are common.

- [ ] "User input can be malicious": is the data actually external, or does it come from a trusted internal source?
- [ ] "Missing validation": the same question.
- [ ] "Behaviour change": do the code comments document it as intentional?
- [ ] "Bug in a test": imagine deleting the feature under test. If the test still passes, it proved nothing.
- [ ] Was the variable traced to where it is really defined?
