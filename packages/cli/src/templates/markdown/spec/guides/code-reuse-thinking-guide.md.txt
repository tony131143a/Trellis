# Code Reuse Thinking Guide

> Before writing new code, ask whether it already exists. Duplicated logic is where a fix lands in one copy and not in the other.

## Before Writing New Code

Search first: for the name you were about to give the function, and for a keyword of its logic.

- [ ] Does a similar function exist? Use it or extend it.
- [ ] Is this pattern used elsewhere? Follow the existing one.
- [ ] Am I copying code from another file? Extract it and import it in both places.
- [ ] Is the same constant defined in more than one file? Keep one source of truth.
- [ ] Is the new component mostly the same as an existing one? Extend the existing one with a prop or a variant.

## Shared Decoding and State

- [ ] Is the same untyped field (JSON, event, RPC payload) read with a local cast in two or more places? Put one decoder or type guard next to the owner of the data before adding a third reader.
- [ ] Is state derived from an action-like value (`action`, `kind`, `status`) in scattered `if/else` branches? One reducer or dispatcher should own the transitions.

## When to Abstract

Abstract when the same code appears three or more times, or when the logic is complex enough to hold bugs. Leave it alone when it is used once, when it is a trivial one-liner, or when the abstraction would be more complex than the duplication.

## After a Batch Change

- [ ] Did the change reach every instance? Search for the old form.
- [ ] Should what was just changed in many places live in one?

## Easy to Miss

- [ ] Adding a value to an enum-like type: have you searched for every `if/else` chain or `switch` on it? A final `else` silently gives the new value the old default.
- [ ] Do two different mechanisms have to produce the same result (a recursive copy and a hand-written list, say)? Make one call the other, or add a test that compares their outputs.

## Before Commit

- [ ] Searched for existing similar code
- [ ] No copied logic that should be shared
- [ ] Each constant defined in one place
- [ ] Similar things follow the same structure
