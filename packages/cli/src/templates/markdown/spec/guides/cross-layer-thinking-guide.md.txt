# Cross-Layer Thinking Guide

> Most bugs happen at the boundaries between layers, not inside them. Think the data flow through before implementing.

## Before Implementing

Map how the data moves: source → transform → store → retrieve → transform → display. For each arrow:

- [ ] What format is the data in?
- [ ] What can go wrong here?
- [ ] Which side validates?

| Boundary | Where it usually goes wrong |
|----------|-----------------------------|
| API ↔ Service | Type mismatches, missing fields |
| Service ↔ Database | Format conversions, null handling |
| Backend ↔ Frontend | Serialization, date formats |
| Component ↔ Component | Props whose shape changed |

## Questions That Catch the Common Mistakes

- [ ] Is a format (a date, an id, a unit) assumed, or converted explicitly at the boundary?
- [ ] Is the same thing validated in several layers? Validate once, at the entry point.
- [ ] Does a layer know about something two layers away, such as a component that knows the database schema?
- [ ] Does every consumer parse the same payload for itself? One owner should hold the type definitions, the guards that normalise untyped input, and the projections the others read.

## Adding an Event, Payload or Config Field

- [ ] Is the new kind or field added where the type is defined centrally?
- [ ] Do filters, reducers and display code read the typed form, not the raw data?
- [ ] Are identifiers (`seq`, `id`, `version`) assigned in exactly one place, and does derived state point back to them instead of inventing a second cursor?
- [ ] If a generated file is also read at runtime (a config, a manifest), can the code that reads it still handle the file an older version wrote?

## Deciding a Mode by Probing

When code picks a mode by probing a resource (does a file exist, does a URL answer):

- [ ] Does the probe run on every path that uses its result, including non-interactive flags and shortcuts?
- [ ] Is "not found" told apart from a transient error? A transient error aborts or retries; it never silently switches mode.
- [ ] Is cached or prefetched state reset when the context changes?
- [ ] Is a response read completely before it is parsed?

## After Implementing

- [ ] Tested with null, empty and invalid input at each boundary
- [ ] Errors handled at each boundary
- [ ] The data survives a round trip
