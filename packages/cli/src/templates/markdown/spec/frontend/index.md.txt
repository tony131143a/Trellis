## Quality Check

After writing code, verify against these guidelines:

1. Run `git diff --name-only` to see what you changed
2. Read the relevant guidelines above for each changed area
3. Always check [quality-guidelines.md](./quality-guidelines.md)
4. Check whether tests need to be added or updated
5. Run the project's lint and typecheck commands — To fill: list the exact commands here

## How to Fill These Guidelines

These files hold the rules of your project: what stays true whichever feature is being built. For each guideline file:

1. Write the conventions the code **actually follows**, not ideals
2. State each as a rule: what must or must not happen, and why when it is not obvious
3. Point at the file, test or lint rule that shows or enforces it, instead of pasting the code
4. Leave out how a single feature works (its flow, fields, error codes): the code and its tests are the source for that

Test each line with two questions: would it still apply to a different feature in the same area, and will it still be true after the next few features land?
