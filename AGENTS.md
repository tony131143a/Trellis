# Arbor Instructions

**First decide which agent you are.**

1. **Dispatched sub-agent**: your first prompt begins with `Active task: <path>` and `Role: explore|architect|implement|review|verify|fix|simplify` (plus `Mode:` for review, `Range: <base>..<head>`, `Dispatch: d-NNN`, and a `Prompt: <file>` line: read that file first, it holds the full prompt). Do that role directly with the context inlined in the prompt (marker `<!-- arbor-hook-injected -->`; if it is missing, read `<task>/implement.jsonl` (architect, implement) or `<task>/check.jsonl` (review, verify, fix, simplify) and every file it lists, then `contract.md`, `design.md`, `waves.md` if present, and `git diff <Range>`). Stay inside your role's write boundary; writers commit on the current branch as `<role>(<task>): <summary>` with trailer `Arbor-Dispatch: <Dispatch>`. Never run `arbor.py` or `task.py start/current/finish`, never push, merge, rebase or switch branches, never write under `.arbor/` outside the task directory. Report in the format your role instructions define.
2. **Main agent**: anything else. Follow `.arbor/workflow.md`, the single source for the state machine, tiers, human gates and commands; specs in `.arbor/spec/`, tasks in `.arbor/tasks/`, journals in `.arbor/workspace/`. Simple changes (at most 2 files, cause known, no design choice) do not use Arbor. Otherwise propose a tier (light / standard / full), write and get approval for `contract.md` (research before start with `arbor.py run --role explore|architect|review` from the brief at the `brief_path` of `arbor.py next --role <role> --json`; independent angles run concurrently), split multi-deliverable requests into a parent plus child tasks (`task.py create --parent`, one session per child), run `task.py start <task>`, then drive the loop yourself: `python3 ./.arbor/scripts/arbor.py --task <task> next` → do the one thing it names → `next` again (`brief`: write it at `brief_path`, then `arbor.py run`; `delegation`: codeg MCP `delegate_to_agent` with `mcp.arguments`, the sync hook `.codex/hooks/sync-delegation.py` binds and collects; `run`: `arbor.py gate` / `arbor.py run`; `decide`: `arbor.py decide impl|contract|fix|skip --reason "…"`; `human`: ask the user at the gates whose `human.mandate` is `ask` (contract, PLAUSIBLE, merge) and always at STOP, `merge_conflict` and scope changes; the user merges `--no-ff`, then `arbor.py finish` cleans up). Act on every entry of the ready set `items` / `batch` in one turn, then wait for `running`. Never perform a role yourself or use native Agent/Task/spawn_agent for one. Prefer `/arbor:workflow`, `/arbor:continue`, `/arbor:finish-work` when available.
